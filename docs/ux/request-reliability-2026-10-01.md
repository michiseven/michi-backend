# 요청 조건·장소 신뢰성 수정 — 2026-10-01

## 관찰된 문제

- 공항 도착 마감·짐 보관/회수 조건이 빠져도 전체 일정 완성으로 표시했다.
- 경복궁 자체 요청에 경복궁 주변 카페가 필수 장소로 선택됐다.
- 음식점이 쇼핑/카페 후보가 되고 홍대 변경 요청에 공덕 후보가 노출됐다.
- 토요일·전체/1인 예산·대상 선택 이전 조건이 유지되지 않았다.
- 실행 검증에서 비행 시각이 관광 종료 시각을 덮어쓰고, 파서 기본 예산이 입력 예산으로 표시되는 추가 결함을 발견했다.

## 변경 계약

- 명시한 날짜·인원·예산·관광 시간 범위를 결정적으로 추출한다. 관광 시간, 체크아웃, 공항 도착 마감, 비행 시각은 별개다.
- 미검증 공항 이동·보관시설은 `partial` 초안으로 공개하고 원문·미확인 조건을 유지한다. 운영시간·비용·도착 보장은 만들지 않는다.
- 지정 장소는 정확한 이름/명시적 다국어 별칭으로 확인한다. 장소명 일부가 같다는 이유로 주변 업소를 대신 지정하지 않는다.
- 제공자 원본 분류로 카테고리를 정규화한다. 대체 후보는 같은 종류·지역·실제 좌표 조건을 만족해야 한다. 후보 부족 시 전국 검색으로 확장하지 않는다.
- 대상 선택 전 요청을 checkpoint에 보존하며 승인 전에 일정에 쓰지 않는다. 명시한 응답 언어를 우선한다.
- 근거 없는 60% 시간 점유율 게이트를 제거한다. 실제 마감·식사·필수 활동 검증은 유지하고 실제 마지막 종료 이후 시간을 자유 시간으로 알린다. 빈 시간 없는 일정을 명시했는데 남는 시간이 있으면 초안이다.
- 정류장 중심 반경은 검색 경계다. 직선 거리로 실제 15분 도보 충족을 보장하지 않는다.
- 운영 재검증에서 `카페 두 곳`이 한 곳으로 줄어드는 결함을 발견했다. 명시적인 방문 개수를 추출하고, 일정 배치에서 우선하며, 최종 검증과 편집에서도 부족한 개수를 허용하지 않는다.
- 안전·접근성 확인이 필요한 일정은 API와 채팅에서도 `partial` 초안으로 표시한다. 공항이 없는 가족 일정에 공항 확인 문구를 붙이지 않는다.

## 확인 범위

- 자동 회귀: 요청 계약, 잘못된 장소 이름/분류, 지역 경계, 대상 선택, 승인, 언어, 공항·짐 후속 질문 및 실제 마감/필수 활동 검사.
- 로컬 PostGIS/Nest 서버에서 실제 HTTP 생성과 조회 흐름 실행. 한국어 브라우저에서 초안·공항 마감·짐 보관/회수·체크아웃 및 후속 답변을 확인.
- 로컬 정상 요청은 토요일 `2026-10-03`, `13:00–18:00`, 전체 `60,000원`을 유지하며 카페와 공원 두 역할을 생성했다(HTTP 201). 출국 요청은 관광 `13:00–16:00`, 체크아웃 `11:00`, 공항 마감 `18:00`, 비행 `20:30`을 구분해 HTTP 201 `partial`로 생성했다.
- 최종 자동 검증: backend 86개 스위트/505개 테스트, frontend 102개 테스트 통과. 두 저장소 lint/build 통과. 상세 재조회에서도 실제 마지막 종료 시각 기준 자유 시간 경고를 다시 계산한다.
- 로컬 장소는 `[MOCK]`로 명시된 테스트 자료이며 운영 장소 검색 성공의 증거로 사용하지 않는다.
- 운영 재검증 결과는 배포 이후 별도 기록한다. HTTP 200만으로 사용자 요구 충족을 판단하지 않는다.

## 남은 제한

현재 제공자는 터미널별 공항 이동과 짐 보관시설의 운영시간·비용·회수 경로를 증명하지 못한다. 해당 요청은 관광 초안과 확인 질문으로 처리한다. 접근성·보행시간은 근거 수준을 노출하며 실제 현장 보장으로 표현하지 않는다.

## 운영 서버 실제 재검증

NAS 기존 SSH 연결로 실제 클러스터를 확인해 immutable 이미지 태그를 적용했다. 초기 자동 배포 대기는 이후 실행됐으므로 영구적인 runner 부재로 판단하지 않는다. 중복된 배포 요청을 정리하고 실행 중인 이미지와 rollout을 직접 확인했다.

- 일본어 관광객: 실제 `경복궁 / attraction / must_visit` 선택, 한식 재질문 없음, 토요일과 1인 80,000원 보존. HTTP 201, 34.2초. 여행 `aa4b027b-a073-4d1f-a83f-862d6a643878`.
- 가족: 총 60,000원, 3명, 10–16시 보존, 서울숲은 `park`, 한식 점심 포함, 마지막 종료 15:40. 유모차는 미검증으로 표시. 여행 `5a1e6e00-2e54-450e-a60c-14e08a7ef2c9`. 초기 서버 완료 표현은 이 재검증에서 발견해 수정했다.
- 출국: 관광 11–16시와 체크아웃 11시, 공항 마감 18시, 비행 20:30 구분. 터미널·이동·보관 근거는 미확인 `partial`. 후속 질문에서 마감 유지, 음식 재질문이나 새 일정 생성 없음. 여행 `b51aed26-3a17-4f73-a308-c2488a221d4b`.
- 카페 교체: 홍대입구역 중심 후보 345–369m, 세 후보 모두 카페, 공덕·스터디카페·음식점 없음. 실제 보행시간은 미검증으로 안내하고 승인 전 쓰지 않았다. 초기 요청의 두 카페가 한 곳으로 줄어든 결함은 성공으로 집계하지 않았다.
- 더 엄격한 맵지 않은 한식 요청은 `MEAL_CUISINE_NOT_FOUND`로 실패를 설명했다. 조건 부족 실패를 생성 성공으로 집계하지 않았다.

비공개 thread/edit token은 기록하지 않는다. 개수·안전 표현 수정 후 운영 재검증에서 두 카페와 공원 생성, 가족 안전 초안 응답을 확인했다.

## 다일 일정 완료 감사에서 확인한 추가 결함

날짜별 방문 개수를 첫날에만 적용하고, 편집에서는 모든 날의 장소를 첫날 시간 범위로 재계산하는 문제를 코드와 회귀 fixture로 확인했다.

- 날짜 지정·매일·여행 전체 수량을 별개로 저장한다. 전체 수량은 앞선 날에 우선 배치하되 첫날의 강제 조건으로 옮기지 않으며 마지막 날과 최종 전체 결과에서 부족한 개수를 검증한다.
- 편집은 원래 날짜별 시간·예산·식사·수량 계약으로 재계산한다. 다른 날짜로 넘어가는 reorder는 거절한다. 고정 일정과 측정된 이동 조건도 보존한다.
- 모든 날을 검증한 뒤 하나의 transaction으로 저장한다. 둘째 날 카페가 부족하거나 날짜를 넘기는 수정은 stop·timestamp·status를 쓰기 전에 거절한다.
- 수정 뒤에도 미검증 공항·안전 조건은 API에서 `partial`로 유지한다. 실패·생성 중 상태는 초안으로 덮지 않는다.
- 자동 검증: backend 87개 묶음·519개 테스트, lint/build 통과. 다일 운영 재검증은 이 변경의 최신 이미지 적용 후 별도로 확인한다.

## 축약 시간 범위와 저녁 일정

홍대 `13~18시` 카페·양식 저녁 2턴 요청을 운영 API로 재현했다. 축약 범위를 인식하지 못해 종료가 20:30으로 늘어난 잘못된 성공도 확인했다.

- 축약 시간 범위를 명시 계약으로 보존한다. 종료 시각을 식사 기본값에 맞춰 연장하지 않는다.
- 사용자가 시각을 정하지 않은 식사는 체류시간까지 요청 범위 안에 들어오도록 기본 시각을 조정한다. 지정한 식사 시각·체류시간은 유지하며, 불가능하면 거절한다.
- optimizer는 식사 조건의 실제 체류시간을 사용한다. 17시/60분 성공, 17시/90분과 18:30 시작의 18시 마감 충돌, 추론한 16:30/90분 종료를 회귀 검증했다.
- frontend는 실패 이유와 회복 선택지를 한 번만 표시한다. 중복 오류 박스를 제거하고 단일 접근성 alert로 안내한다.
- 자동 검증: backend 87개 묶음·537개 테스트, frontend 103개 테스트, 각 lint/build 통과. 운영 재검증은 새 이미지 적용 후 기록한다.

## 내부 미배정 시간과 식사 기간 추가 감사

운영에서 홍대 카페 13–14시·양식 저녁 17–18시 생성을 확인했다. 종료 시각은 유지됐지만 두 활동 사이의 긴 미배정 구간이 채팅에 드러나지 않았다. 이후 `저녁은 17시에 90분 동안 먹을 거야`는 90분을 놓치고 60분으로 줄인 잘못된 성공을 확인했다(여행 `eeaccd2d-f43c-433d-b4ff-6d9888d1f8a7`).

- 내부 구간을 저장된 시각과 이동 근거로 안내한다. 실제 측정 이동만 제외하며 추정·혼합·결측 이동은 활동 미배정 구간에 포함해 설명한다. 30분 미만의 일반 이동은 별도 경고하지 않는다.
- 날짜별 안내가 생성·GET 재조회·한국어·일본어에서 유지되도록 검증한다. 미배정 구간을 메우려고 임의 활동이나 체류시간을 추가하지 않으며 완료 판정도 변경하지 않는다.
- 식사 시각과 기간이 함께 있는 문장을 보존한다. 17시부터 90분 식사와 18시 종료는 충돌하므로 기간 축소·시각 이동·종료 연장 없이 거절한다. 카페 체류시간은 식사 기간으로 옮기지 않는다.
- 추가 자동 검증: backend 88개 묶음·559개 테스트, lint/build 통과. 운영 재검증은 새 immutable 이미지 적용 후 별도 증거 파일로 기록한다.
